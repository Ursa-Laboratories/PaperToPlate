# Explore a question

Open http://127.0.0.1:8785/?explore=1.

1. Describe what you want to learn. Red, yellow, blue and water are listed
   above the question; click a stock to edit its description. The deck below
   comes from CubOS. If disconnected, it is explicitly labeled Recorded setup.
2. Explore the papers returned by Valency Bond. Each paper keeps its source
   link, abstract evidence, a proposed experiment and any extra equipment.
   These suggestions are not presented as extracted numerical protocols.
3. Choose an experiment. The supported RYB method retrieves its full six-page
   paper and asks the AI for parameters. Inspect the proposed volume, dye
   fraction, well count and deck allocation; physical offsets are separate.
4. Generate the experiment. The source-specific compiler checks stock
   proportions, well totals and tips, then runs native CubOS validation.
   There is no independent-review dialog in this flow.
5. Load the listed stocks, check the physical setup, and use Run in CubOS.
   A disconnected or recorded setup cannot submit hardware work; reconnect
   and prepare again from current station inventory first.

The current directly prepared method is Ginsburg et al., Exploring Benchmarks
for Self-Driving Labs using Color Matching, https://arxiv.org/abs/2310.00510.
Its CMYK approach is adapted to RYB; its optimizer and numerical recipe are
not claimed as reproduced. Other abstract-only leads offer the existing
full-paper upload/extraction path before an executable method is prepared.

The AI proposes parameters; the bounded compiler emits the actual transfers.
The new preparation path uses explicit recipe checks instead of an independent
LLM verdict. Existing free-form PDF-generation rules and historical evidence
remain intact. Native validation, actual loading confirmation, current station
checks and duplicate-submission prevention still apply. Editing native YAML
invalidates its review/check basis. The recorded demonstration links to an
already completed run; viewing it never starts another experiment.

Edited demonstration videos are kept outside the repository. They combine
the software walkthrough with clearly labeled footage of the completed run.
